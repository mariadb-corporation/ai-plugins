# Gotchas / things not to repeat

[← Project Context](../PROJECT_CONTEXT.md)

## DevHub, CSS and headless Chrome

- **A negative-`z-index` pseudo-element paints ABOVE its parent's background only if the parent establishes a stacking context** — otherwise it drops into the nearest ancestor's negative layer and the parent's own background covers it. In `style.css`: `.btn--primary` needs `isolation: isolate` for its `::before` overlay to sit above the fill and below the label; and **`container-type` must NOT go on `.hero__card`** — layout containment would make the card a stacking context and its `::before` bloom (behind the card at `z-index: -1`) would paint over it. The container is on `.hero-panel`, which already has `z-index: 1`.
- **`background-image` is not animatable, so a two-layer background swap always snaps.** For a crossfade, animate an overlay's `opacity` with the gradient left in place underneath.
- **Panel width is NOT monotonic in viewport width, so "the element is narrow" cannot be a media query.** The hero card is 679px wide in a 768px viewport but 361px at 901px, where the hero splits into two columns. Measure the element and use a container query.
- **An absolutely positioned overlay inside a scroll container scrolls away with the content.** A "there's more →" marker must live on a box that does not scroll — hence `overflow-x` sits on the `<pre>`, not the panel body.
- **`docs/serve.sh --build` wipes `docs/_site`**, so probe/harness files dropped there vanish on the next build (gitignored, which hides the loss).
- **Headless Chrome won't reliably fire `scroll` events for an offscreen iframe, and `requestAnimationFrame` may never run under `--virtual-time-budget`.** Dispatch the event yourself (`el.dispatchEvent(new Event('scroll'))`) and assert on the resulting class/computed style.
- **Headless Chrome has a minimum window width (~500px)**: `--window-size=390,…` lays the page out wider and merely crops the screenshot. Use CDP `Emulation.setDeviceMetricsOverride`, or measure `documentElement.scrollWidth > clientWidth` inside a sized `<iframe>`. A small CDP driver (`Runtime.evaluate` + `Page.captureScreenshot` over the `--remote-debugging-port` WebSocket, Node 24's global `WebSocket`) is enough to click and measure. `--blink-settings=preferredColorScheme=1` gives light (0 = dark).
- **An `EXIT` trap never fires after `exec`.** A script that must clean up cannot `exec` its final command; run it as a child and forward the status.
- **Jekyll picks its config parser from the file EXTENSION** and silently ignores anything not `.yml`/`.yaml` — a `--config` at an extensionless `mktemp` file builds with defaults (wrong `baseurl`). Make the *directory* random and the file inside it fixed.
- **`Gem::MissingSpecError` is NOT a `StandardError`** (`Gem::LoadError < LoadError < ScriptError < Exception`); rescue `Gem::LoadError` explicitly.
- **macOS's `/usr/bin/gem` has a gem set unrelated to a Homebrew Ruby's.** An editor launched from the Dock often has `jekyll` on PATH but not Homebrew's `gem`. Ask the Ruby that will run the tool (read the shim's shebang).
- **Liquid `{%- -%}` eats whitespace inline menus depend on** (separators assume a glyph between `<li>`s; emit `{{ ' ' }}`). And mariadb.org's root font size is **22px**, ours 16px, so its `rem` values don't copy over.
- **A "dead" DevHub button after a JS change is usually a cached `site.js`** — hence the `?v=<build time>` on both assets; don't remove it.
- **`[hidden]` comes from the UA stylesheet, so ANY author `display` rule beats it.** Keep the global `[hidden] { display: none !important; }` — the `!important` is load-bearing.

## Shell, MCP server and sandboxes

- **`sandbox.deploy` registers a connection; `db.connect` needs no password.** It calls `config.store_connection("root@127.0.0.1:<port>", password)`; `db.list_connections` is derived from those *secrets*. So the registration is only visible through the config home holding the secret store, and an **unreadable secret store makes every connection look unconfigured**.
- **Don't judge credential-touching behaviour from an SSH session on Windows.** The Windows credential store needs an interactive desktop logon, so over SSH secret-reading tools fail with `Cannot list secrets, current credential helper is invalid`. SSH is fine for process/MCP-wiring checks.
- **`releases/latest` of mariadb-shell 404s while every release is a prerelease** (the endpoint excludes them) — not because of privacy; the repo is public. Check with `gh release list -R mariadb-corporation/mariadb-shell`. An unattended install depends on the launcher's prerelease fallback until a stable release exists.
- **A source build of mariadb-shell reports its upstream version** (`Ver 9.x`), so the floor gate rejects it on PATH; point `MARIADB_SHELL_BIN` at it.
- **Installer targets**: `install.sh` unpacks to `~/.local/share/mariadb-shell/<ver>/`, symlinks `~/.local/bin/{mariadb-shell,msh}`, keeps the 2 newest versions, and **only prints a PATH hint — never edits a shell profile**. `install.ps1` → `%LOCALAPPDATA%\Programs\mariadb-shell\`, `bin\*.cmd` shims. Both honour `MARIADB_SHELL_PREFIX`/`_BINDIR`; `install.sh` needs curl+tar+awk, plus jq or python3 on the API path (token or `--pre-release`).
- **mariadb-shell's Windows packages have shipped without pywin32** (checked through 26.8.1, arm and x86), so `mcp start-server` dies with `ModuleNotFoundError: No module named 'pywintypes'` while `--version` works; a `pip install pywin32` into the bundled Python fixes it. Check a newer Windows package before assuming it's fixed.
- **Testing a resolution chain: measure the branch, not the outcome.** A rejected binary is still launched by the install-failure fallback, so "did the shell get launched" reports ACCEPTED for every version. Assert on the launcher's own stderr line; stub binaries cover the table cheaply.
- **All file-touching MCP tools are path-gated** by `<config home>/plugin_data/mcp_plugin/settings.json` `allowedPaths`; a non-allowed path falls back to an elicitation a headless client can't answer. MSM tools fail the call; `sandbox.deploy` **HANGS** — always pre-seed the allow-list. The `msm` plugin method is `msm.create_new_project_folder` (not `create_project`); `license="GPLv2"` is rejected — omit it or pass custom text.
- **Seed the allow-list with BOTH macOS path spellings** (`/var/folders/...` and `/private/var/folders/...`); the guard compares strings. With only one, the model reports the path "not registered" and falls back to the shell CLI, producing genuine MSM artifacts with no MCP call — which is why the MSM e2e also checks for completed `msm.*` calls.
- **Shell config home**: `~/.mariadb-shell` (log `mariadb-shell.log`); relocate with `MYSQLSH_USER_CONFIG_HOME` and `MARIADB_SHELL_USER_CONFIG_HOME` (set both). **The shell loads its plugins from the config home**, so a bare temp config home kills the MCP server (`There is no object registered under name 'mcp'`) — isolate it *and* link the real plugins in (what `lib/sandbox.py` does). The dir must already exist, or the shell dies on "Error opening log file". In a development setup where plugins are symlinks into a shell-plugins checkout, a moved or renamed checkout breaks them the same way and the whole db tier **skips** (not fails) — check those links first.
- **`db.execute_sql_script` runs the whole script on the connection's ONE session** (`use_session` in `mcp_plugin/lib/db_functions.py`): `SET @x` then `SELECT @x` works, `CONNECTION_ID()` is constant, `USE` carries over, `ROLLBACK` undoes an `INSERT`, a full REST DDL sequence works as one script. A script is not a transaction; a failed statement is reported in its entry (`stop_on_error=True` stops there); state is lost only when an idle or dropped session is reopened (`session_restarted: true`).
- **`db.connect` normalizes the uri**: a `mariadb://` prefix (but not `mysql://`), host case, the default port and an inline password all fold onto the stored `root@127.0.0.1:PORT` key. A uri asking for **more** than was configured (`…/schema`, `?ssl-mode=REQUIRED`) is refused as "not a configured connection", deliberately. `db.execute_sql_script` rejects file paths outside allowed paths → pass SQL inline.
- **MSM deployment composition:** sections **140/240/170/270** become **stored-procedure bodies** → plain `;`-terminated, NO `DELIMITER`, dynamic SQL for conditional DDL; **130/150/230/250/190/290** are top-level with `DELIMITER %%`. Order: `prepare_release` → **fill the update script** → `generate_deployment_script` → `deploy_schema` (generating first yields a script that creates fresh but can't upgrade). Section 250 is never deployed (views/routines go in 150, removals in 240); 270 is only for `REVOKE`/`DROP ROLE` (grants in 170, which runs on every deployment).
- **MSM SOURCE breakout:** `SOURCE './sections/x.sql'[start:end];` slices strip each file's own header/footer: character offsets (`[53:]`, `[663:-115]`), or, with a shell newer than 26.10.2 (mariadb-shell-plugins #60), line numbers `lnN` (1-based, end included, `ln-1` last) and no slice = whole file; relative to `development/`; inlined at `prepare_release`.
- Timeouts orphan sandboxes if teardown isn't in a `finally`. Clean via `sandbox.stop`+`sandbox.delete` (fallback `sandbox.kill`; `delete` refuses a running instance). Root password must not be blank. Deploy with `ssl: False` to avoid needing openssl.

## Scripts, git and releases

- **Batch files must be CRLF and ASCII** — `.gitattributes` sets `text eol=crlf`, so git stores LF blobs and checks out CRLF; don't "fix" the LF blob. LF-only batch files mis-parse `goto` labels and `^` continuations. `*.SHA256SUMS` are kept LF (`install.sh` reads them line by line).
- **A licence header in a `.cmd` must go AFTER `@echo off`** — `rem` lines above it echo to **stdout**, which for the launchers is the MCP transport.
- **bash 3.2 (macOS) + `set -u`:** guard empty-array expansion (`[ "${#arr[@]}" -gt 0 ]`).
- **`env` options must precede the assignments.** `env FOO=1 -u BAR cmd` runs `-u` as the command and exits 127 — read the exit code before concluding anything.
- **`sed -i` on macOS drops a script's executable bit** (BSD `sed -i` writes a new file). Check `git diff --summary` for `mode change` on any PR touching a script; fix with `git update-index --chmod=+x`.
- Background `... | tee log` reports **tee's** exit (0) — read the pytest summary line.
- **Editing `additional-skills/` without re-running `scripts/sync-skills.sh` silently ships stale text** — caught by `test_additional_skill_matches_its_source`.
- **A sync at upstream `main` can be a no-op or mass churn** (e.g. a footer added to every skill). Read `git status` / `git diff --shortstat` + one sample diff before assuming it shipped content.
- **Compare file counts with `git show --name-only`, not `--stat`** (which truncates long paths).
- **`git fetch origin fork` does NOT fetch two remotes** (the second word is a refspec). Use `git fetch --multiple --tags origin fork`; loop for `ls-remote`.
- **Squash merges leave branch commits unreachable from `main`**: check containment by tree or against the PR's `headRefOid`, never by ancestry.
- **`gh release create` cannot combine `--notes-from-tag` with `--repo`.** Extract the body (`git tag -l --format='%(contents:body)' <tag>` → `--notes-file`), which also gives both repos identical notes. Always pass **`--verify-tag`** (otherwise a typo'd tag is created). Give the annotated tag a one-line subject, `MariaDB AI Plugins <version>`, so the whole summary lands in `%(contents:body)`. GitHub appends one trailing newline to a release body, so strip trailing whitespace before comparing; macOS BSD `sed` rejects the usual trailing-blank-strip idiom and silently yields nothing, faking a passing comparison. The prerelease flag stays editable after publishing (`gh release edit --prerelease`) unless the release is immutable.
- **Slash-command placeholders: only `$1` (and `$ARGUMENTS`) expand; `$2` arrives literal.** Any command with more than one argument takes `$ARGUMENTS` and splits it itself (as `release.md` does); if a body shows a literal `$N`, read the arguments off the user's command line.
- **Read `git status -sb` before `git commit`** — the user may have switched branches mid-session.
- When writing a re-vendor commit message, take the upstream commits per plugin from `skills-source.json`, not from the order `git diff` lists plugins in (contributor sorts before dev).
- **`set-mariadb-shell-version.sh`'s "N file(s)" is the number it SCANNED, not changed.**
- **docs-ref skill pages are generated: hand edits are lost.** Regenerate with `python3 docs-ref/scripts/generate-skill-pages.py` and diff.

## Harnesses

- **Codex spawns MCP servers with a FILTERED environment.** An exported `MARIADB_SHELL_USER_CONFIG_HOME` doesn't reach the server, so it uses the real config home and its allow-list, rejects the throwaway project dir, and the model falls back to the `mariadb-shell` CLI (correct artifacts, zero MCP calls). Declare env in the server's own entry: `-c 'mcp_servers.mariadb.env={MARIADB_SHELL_USER_CONFIG_HOME="…", …}'`. A stale test path left in the real allow-list can make a first run pass misleadingly.
- **`subprocess.run` on `codex exec` MUST pass `stdin=subprocess.DEVNULL`** — codex reads a piped stdin as extra prompt input and blocks forever (symptom: hang with an empty event stream).
- **Don't assert model obedience and call it wiring.** Tests demanding a fixed output shape (only `msm.*` tools; "list four skill names") went red while the plugin was fine. Assert the side effect the plugin controls; keep preference checks separate.
- **pi ignores project-local packages unless the run passes `--approve`/`-a`** — `pi install -l` reports success, then the skills are silently absent. **`pi list` reads only user settings**, so it proves nothing about a project-local package. `pi install <path>` writes just the path and runs no `npm install`; `pi install -l --approve <path>` in a throwaway dir touches nothing global.
- **pi exposes no skill/package data in its event stream** (`--mode json`), and the extension's `session_start` notify doesn't surface in `-p` mode. Evidence that skills loaded is behavioural (the generated script's Start Block) plus matching the reply against the real vendored names.
- **The pi e2e usually runs on a local OpenAI-compatible model**: free but weak on long instructions, and `pi auth check --provider <x>` reports `not_ready` even when runs succeed — so the gate uses a trivial round trip.
- **Pi 1.0 MCP:** an installed `pi-mcp-adapter` *replaces* the built-in MCP (it registers `/mcp`), and on first run **Pi writes `"extensions": ["-builtin:mcp"]` into `~/.pi/agent/settings.json`**. Migration: `pi remove npm:pi-mcp-adapter`, re-enable `mcp` in `pi config`. The adapter's `~/.config/mcp/mcp.json` is not read by Pi.
- **`pi mcp list` and `/mcp` in `-p` mode don't show the extension's server** (shell `pi mcp` loads no extensions). Verify via a codemode call.
- **Codemode helpers are async and tools live on `tools.`**: `await describeNamespace("mcp__mariadb")`, `await tools.mcp__mariadb__db_list_connections({})`. A model that forgets `await` logs `{}` and concludes the server is empty — hand it the exact script.
- **An e2e model can reach the user's saved connections over MCP.** Prompts must pin the scope and forbid DB access, or an open-ended schema prompt creates/drops objects on a real server until the timeout.
- **Hermes' install scan, not `--force`'s help text, decides whether `--force` is needed.** `plugins install --force` (documented as "reinstall") also overrides a BLOCKED verdict (community source + *caution*). The scan reads every `SKILL.md`: `sudo` lines rate HIGH (`privilege_escalation`), so a vendored skill reintroducing `sudo` blocks dev/sql again — the e2e installs without `--force`, so it catches that. By hand: copy `hermes/` into a throwaway git repo, `hermes profile create <tmp> --no-skills`, `hermes -p <tmp> plugins install file://<repo>#hermes/dev-plugin --enable --yes-deps`, `hermes profile delete <tmp> --yes`.
- **Hermes catalog reviewers edit entries when they merge them** (#145982: `Disclosure:` → `Disclosure —`, plus an email mapping file). Edit the catalog YAML as it stands on hermes-agent `main`; pasting in an earlier copy silently reverts them. Catalog CI rejects commit emails not mapped under `contributors/emails/` — commit as the GitHub noreply address (or `mike.zinner@mariadb.com`, which the reviewers mapped to `mariadb-MikeZinner`); a catalog PR may touch only `plugin-catalog/**` and `contributors/emails/**`.
- **Hermes passes MCP stdio servers only `PATH HOME USER LANG LC_ALL TERM SHELL TMPDIR XDG_*` + the `env` from `mcp.json`.** A "clean install" test must write `MARIADB_SHELL_BINDIR` into the staged `mcp.json`, or the launcher installs into the real `~/.local`. Language servers get the (credential-scrubbed) full env plus their own `env`.
- **Hermes skips a language server for the whole session after one missed budget** (`wait_timeout` 5 s, `warmup_timeout` 0, `broken_retry_seconds` 0). A first start waiting for the shell download needs `lsp.warmup_timeout`.
- **Claude Code: per-server MCP timeouts and plugin `settings.json` env are ignored** — only `MCP_TIMEOUT` moves the 30 s connect timeout (`MCP_CONNECT_TIMEOUT_MS` doesn't, for stdio).
- **"Clean install" means stripping dev builds from PATH too** — a source-built `mariadb-shell`/`mariadb-lsp` on PATH is silently picked up. The e2e tests drop every PATH dir holding either binary.
- **In Claude's debug log the MCP and LSP servers share the name `plugin:<plugin>:mariadb`.** Filter LSP lines on `LSP` and exclude `MCP server`.
- **Running `claude -p … --dangerously-skip-permissions` from a session is blocked by the auto-mode classifier.** Use `--allowedTools` with just what the run needs (the LSP e2e uses `Write,LSP`).
- **The Claude LSP e2e on a clean install needs the model to retry the `LSP` tool** while `mariadb-lsp` waits for the download; the prompt allows ten retries.
- **Claude Code on native Windows runs a `.sh` MCP/LSP command through `bash`**, and Git for Windows puts only `Git\cmd` on PATH ("'bash' is not recognized"; LSP: "exceeded max crash recovery attempts (3)"). Hence the extensionless commands, resolving through `%PATHEXT%` to the `.cmd` (verified with Claude Code 2.1.306 on Windows 11 ARM64).
- **OpenCode gives a language server a fixed 45 s (`INITIALIZE_TIMEOUT_MS`, 1.19.3) and marks a failed one `broken`** for the instance; no config changes it. `opencode debug lsp diagnostics <file>` exercises LSP servers without a model (prints `{}` on failure).
- **OpenCode on Windows: `{env:VAR}` is pasted into the JSON text before parsing**, so a backslash path invalidates the whole config (`InvalidEscapeCharacter`) — use forward slashes. Its program lookup walks `%PATHEXT%` like Claude Code's.
- **OpenCode's free models are unreliable** (< 1.18 gets HTTP 426; 1.19.3's free models often don't answer), and with `GOOGLE_API_KEY` set it defaults to Google and wants `GOOGLE_GENERATIVE_AI_API_KEY`. A model-driven OpenCode test needs `opencode auth login`.
- **`@opencode/cli` (2.x) is NOT `opencode-ai` (1.x).** 2.x accepts the `lsp` block but has no LSP runtime, no `debug lsp`, a different `models` CLI, and credentials in `opencode.db`, which 1.x refuses ("has no session table").
- **A multi-line prompt through an npm `.cmd` wrapper (`opencode.cmd`) is cut at the first line break** — keep e2e prompts on Windows to one line.
- **Windows over SSH**: cmd prints "The system cannot find the path specified" on every command and one-liners with `for`/`&&`/`||` garble. Use PowerShell with a simple `-Command`, or copy a Python script over.
- Foreground `sleep` is blocked by the harness; use `run_in_background` / Monitor.
- `see_also_refs()` counts only backticked `mariadb-*`/`mysql-*` under `## See Also`; underscored names like `mariadb_rest_service` don't match (safe).

## Videos (`videos/`)

- **espeak-ng ignores a data path longer than 160 chars** and falls back to a compiled-in CI path ("Error processing file … phontab"). Fix: the short `videos/.cache/esd` copy `setup.sh` makes.
- **A moved venv** still runs via `bin/python`, but `bin/pip` keeps the old shebang — call `python -m pip`.
- **Kokoro pauses at word boundaries**: two-word spellings ("Maria DB", "AI Plugins") get a 60–180 ms gap; a hyphen joins them into one phoneme word. Joining "AI-Plugins" moves the breath to before the word instead. A comma gives ~290 ms, a dash ~310 ms; the user found even 200 ms too long after "MariaDB".
- **Page engine**: a child with `visibility:visible` shows through a hidden scene (hide scenes with `display:none`); `applyFx` overwrites `transform`, so a CSS `translateX(-50%)` centring on an animated element is lost (anchor with left/right).
- **macOS `say`** has only robotic standard voices unless the user installs Premium ones.
